# Bridge Input Repair A/B/C/D Mini-Pilot — 报告

**结论：`REPRESENTATION_ONLY`。** 标准化输入（B、D）确实让同一道题两个 Plan 的 Latent 明显分开。但在 held-out 题上，冻结的 Executor 对两者的执行评分没有可靠差异；方法切换只在 1 道 held-out 题上出现。B 组在训练题上的 margin 明显上升，属于只在训练题上起作用、不能泛化。

本实验是在 20+8 对数据上训练期 Bridge 的诊断，不代表 Latent Planner 的性能。

## 设置（四组只改 Bridge 输入，其余逐项相同）

- **Executor / 编码器**：Stage-1 step 800（HF a6b0e2fe），冻结，bf16。
- **数据**：Mini-Pilot 的 20 train + 8 held-out，sha256 与原文件一致，没有剔除任何样本。
- **Bridge**：结构、初始化（seed 0）、数据顺序（seed 1234）都与之前相同；每步 4 对；AdamW，lr 1e-4，wd 0.01；梯度裁剪 1.0；λ_rank = 0.1。
- **Loss**：L = ½(CE_full(E_A|Z_A) + CE_full(E_B|Z_B)) + 0.1·[softplus(−Δ_A) + softplus(−Δ_B)]。
  - 按任务书，Δ 只在**前 64 个执行 token** 上计算，两种 Z 用同一组位置和 mask。
  - 原 Pilot 的 Δ 是对整段 Execution 取平均，所以 **A 组按新定义重跑**，保证严格可比。旧的 A 结果（整段 margin +0.00025）仅作参考。
- **训练**：每组 100 步，每 10 步评估；主结论看 step 50，step 100 只看趋势。每步约 3.6 秒，显存峰值 68 GB。

### 输入表征：对任务书定义的必要改动

- 原 Bridge 对 **Plan token 状态序列**做 cross-attention，输入不是单个 boundary 向量。如果只输入一个向量，8 个 slot 会得到完全相同的输出，Bridge 就退化了。因此四组统一使用第 27 层的 Plan token 序列。
  - **A**：原始状态。
  - **B**：用训练集 token 统计量做逐维标准化。σ 下限取第 5 百分位（5% 的维度被抬到下限）；截断阈值 ±5，实际被截断的比例为 0。
  - **C**：每个 token 状态减去 h_null(Q)。h_null 取 `Q + <EXPLORATION>\n + 空 Plan + </EXPLORATION><EXECUTION>\n` 最后一个 token 的第 27 层状态。
  - **D**：对 C 的残差做标准化，统计量由训练集残差单独估计。
- 任务书字面定义的 boundary 向量单独做了审计：同题 A/B 的原始 cos = 0.9962，残差 cos = 0.9749。
  - **限制**：h(Q,P,b) 与 h(Q,∅,b) 的绝对位置相差一个 Plan 的长度，因此残差里混有 RoPE 位置和长度的影响。C/D 中把同一个 boundary 向量从不同位置的 token 状态里减掉，同样不是纯粹的 Plan 表示。逐题的位置和长度记录在 `group_*/input_representation_audit.json`。

## 方法切换的人工判定

自动指标的判据是：Z_A 的生成与 E_A 的 4-gram 重叠更高，且 Z_B 的生成与 E_B 的重叠更高。我逐条读了自动判为切换的全部 6 例：

- **s1val-00305，B 与 D 的 step 50：真实切换。**
  - Z_A：代入 y=6/x，化成二次方程，与方法 A 一致。
  - Z_B：xy(x+y)+(x+y) = (xy+1)(x+y)，求出 x+y=9，再用 x²+y² 恒等式，与方法 B 一致。
  - 答案：D 两边都对；B 的 Z_A 一边算错。
  - 这道题在 A、C 两组中都没有切换。
- **不算切换的情况**：
  - B step 100 的 00569：Z_A 用判别式，符合方法 A；但 Z_B 走了“常数加有理式”的第三种方法，不是求导。
  - B step 100 的 00479：Z_A 只写了一段同时提到因式分解和 Vieta 的计划就结束了。
  - D step 100 的 00479：Z_A 与 Z_B 都用 Vieta。
  - A step 100 的 00486：两边都不是参考方法。
- **结论**：step 50 时 B 和 D 各有 1/8 题出现可信切换，并且是同一道题。A 和 C 为 0/8。

## 解读

1. **输入标准化解决了表示层面的问题**：cos(Z_A, Z_B) 从 0.999 降到 0.79–0.90，输入端的 A/B 差异显现出来。离群维确实是导致 Bridge 输出塌缩的原因之一，这次对照为此提供了证据。
2. **执行端仍然不能泛化**：
   - B 组在训练题上的 margin 快速上升，100 步时达到 0.075；held-out 却为负。这是在 20 对数据上逐题记忆，不是学到了“方法 → latent”的映射。
   - D 组的 held-out margin 为正，但 CI 包含 0，在 8 道题上不能算信号。
3. **附带观察**：D 组 step 50 的 16 次生成全部正常结束并给出 \boxed 答案，正确率 14/16。A/C 组有 5–8 次只写出计划式文本就结束，没有答案。D 的 Z 对 Executor 的干扰最小，但这不是方法控制，不计入结论。

## 决策与建议（未执行）

- **判定为 `REPRESENTATION_ONLY`**：
  - 不建议继续调整输入数值，也不建议改随机种子或扩大步数。
  - 瓶颈已从表示层转到**训练目标和数据规模**：20 对数据 + 8 个 slot + CE 主导的目标，Bridge 只能记住训练题。
- **可讨论的方向**：
  - 用文字 Plan 条件下 Executor 的状态（KV 或 hidden）做蒸馏目标，给 Bridge 提供逐 token 的密集监督；
  - 把双 Plan 数据扩大到 100–200 对，生成和筛选流程已经跑通；
  - 少量 Executor conditioning，需用户批准。
- 本次没有做 LoRA、Stage 2 训练、RL 或新的 Loss。

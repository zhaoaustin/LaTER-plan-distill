## 设置要点

- **Z 的来源**：冻结的 Stage-2A step-300 Compressor 生成 8×2560 的 Z 并缓存。只读 Plan 文本，经身份验证无误；没有使用 0.6B 的 Adapter。
- **Executor 输入**：`chat(Q) + <EXPLORATION>\n + 8 个 slot（Adapter(Z)）+ </EXPLORATION><EXECUTION>\n`，其后接 Execution 目标；与之前所有 latent 实验的格式相同，前缀中没有任何 Plan、标签、Execution 或答案文本。
- **训练参数**：只训练 Adapter（LN + 恒等初始化的 Linear + 可学习尺度，656 万参数）和 LoRA（r16，q/v/o，973 万参数）。骨干冻结，训练前后核验不变。
- **Loss**：每张卡 4 条单样本的 Execution CE，加 1 对 verified pair 的 CE 和 0.1×ranking（只在前 64 个执行 token 上算，实现与之前的 Bridge 和 LoRA pilot 相同）。
- **双卡**：torchrun world=2，梯度 all-reduce 取平均；全局 batch 为每步 8 条单样本加 2 对；两卡参数在 step 1 和 step 50 完全一致；step 10 时利用率 98% / 94%。
- **训练量**：50 步，用时 43 秒；前 10 步计入 50 步，用来测速。

## 三个问题

1. **Stage-2A 的 8-token Z 在新题上有没有指导 Qwen3 的 Explicit CoT？基本没有。**
   - held-out 上，正确 Z 对同题交换 Z 的整段 margin 为 +0.0009 [−0.0001, +0.0021]，前 64 token 为 +0.0005 [−0.0007, +0.0018]。
   - 跨题 Z、均值 Z、零 Z 与正确 Z 的差都在 ±0.003 以内。
   - 自由生成 1/8 切换（step 0 为 0/8）。
   - 训练 CE 和 held-out CE 的下降与 Z 无关。
2. **失败更像 Encoder 没保存方法，还是 Executor 没学会使用？倾向于后者，但严格说是 `INCONCLUSIVE`。**
   - **支持 Executor 一侧的证据**：Stage-2A 已证明 Z 含有可读的、与题目相关的 Plan 信息（0.6B Decoder 上打乱 Z 比正确 Z 的 CE 高 0.40，同题 A/B 的 Δ 8/8 为正）；但 2B 中连换成完全不相关题目的 Z（跨题 Z），执行 CE 也几乎不变，说明 Executor 基本忽略了 Z。
   - **2A 能清楚切换的 3 对中，2B 只切换了 1 对**（00336），所以不能全部归因于上游。
   - **另一方面**：只训练了 50 步（每张卡 200 条单样本和 50 对），2A 的方法语义本身也只部分成立（3/8 清楚），因此无法排除训练量不足和上游语义两种因素。
   - **与旧 Bridge + LoRA 的对比**：那次训练题 margin 达到 0.27，这次只有 0.015。原因是本次按任务书把大量单样本 CE 与少量 pair 混合，对比信号被稀释。这只是设计层面的差别，两次实验不是同条件比较。
3. **下一步：不建议进入 Stage 2C，先修 2B。**
   - 2B 的接口还没有证明 Z 能驱动执行。
   - 可讨论的方向（本次都没有执行）：
     - 增加 verified 同题双 Plan，流程已经跑通，可扩到 200 对以上，让对比监督占主导；
     - 让 loss 只作用在 Execution 开头、真正做出方法选择的区域，或提高该区域的权重；
     - 先确认 Executor 在只用 pair 数据训练时能否在 held-out 上切换，再混入单样本。

# 生成路径阳性对照：在 20 道训练题上，分别用 Z_A、Z_B 做 greedy 自由生成

- 设置：同一批缓存的 Z，同一套注入与生成代码，最多 1024 个 token。

| | 不加 LoRA（冻结 Executor） | LoRA step 50 |
|---|---|---|
| 自动判定的切换候选 | 2/20 | 6/20 |
| **人工判定：清楚的方法切换** | **0/20**（另有 1 道部分切换：00313） | **5/20**（另有 1 道部分切换：00689） |
| Z_A 与 Z_B 生成逐字相同 | 1 | 0 |
| 答案正确 / 40 | 23 | 19 |
| 正常结束 / 40 | 37 | 20（未结束的都是长计算超出 1024 token，没有重复循环） |

## 人工判定明细

**LoRA 组**
- 00645：积化和差 vs 等差角公式，切换。
- 00683：正弦定理 vs 作高，切换。
- 00626：欧拉函数公式 vs 容斥原理，切换，两边都答对。
- 00496：点积 vs Cauchy-Schwarz，切换，两边都答对。
- 00344：令 f(x)=0 逐个试值 vs 作图，切换。
- 00689：Z_B 用对数，与 Plan B 一致；Z_A 用有理部分与无理部分分别相等，不是 Plan A 的写法，算部分切换。
- 有几条生成与参考 Execution 的 4-gram 重叠达到 0.94–0.96，几乎逐字复现训练文本，属于记忆。

**不加 LoRA 组**
- 00660：两边都用分组因式分解，Z_B 没有做 z=y−1 换元，不算切换。
- 00313：Z_A 先试对称情形，Z_B 先分析单调性，算部分切换。

## 结论

- 从 Z 到 Executor 自由生成方法的整条链路是通的：LoRA 训练后，训练题上能看到真实的方法切换（5/20 加 1 道部分切换），不加 LoRA 时是 0/20 加 1 道部分切换。
- held-out 上是 0/8，所以失败原因是泛化（训练题被记住），不是管线 bug。
- 另外，即使训练题 margin 有 0.27，greedy 生成也只有约 1/4 的题切换。说明前 64 个 token 上的 margin 只能部分转化为生成时的方法选择。
